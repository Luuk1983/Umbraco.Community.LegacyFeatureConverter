# LP.Umbraco.LegacyFeatureConverter — Implementation Plan

## Context

This project is an Umbraco 13 plugin that converts legacy property editor content to modern formats. The codebase is currently an empty skeleton — only the solution structure, a plugin `.csproj` (Razor SDK), and a test Umbraco instance exist. No C# business logic has been written yet.

We have a reference project at `C:\GitHub\Old__UmbracoLegacyFeatureConverter` with proven patterns (Template Method converter, EF Core auditing, scope-per-save, test-run support) that we'll adopt and improve upon.

The user wants TDD, separation of concerns, extensibility, localization, background processing, and high-quality maintainable code.

- `Models/ConversionProgress.cs` — For SignalR: Phase, CurrentItem, ProcessedCount, TotalCount, PercentComplete
- `Services/IConversionHistoryService.cs` — Start, Log, Complete, Get, List
- `Services/IConverterService.cs` — GetAllConverters, GetByName, GetMetadata, GetAffectedDocTypes

## Phase 2: Data Layer (Entity Framework Core)

**Goal:** Database persistence for conversion history, logs, and queue using Entity Framework Core — the ORM that Umbraco 13 supports natively. This is a dedicated project containing only database concerns.

### Files in `.Data/`

- `Entities/ConversionHistory.cs` — EF Core entity for conversion records
- `Entities/ConversionLogEntry.cs` — EF Core entity for detailed log entries
- `Entities/QueueItem.cs` — EF Core entity for persistent queue

### Files in `.Data/Context/`

- `LegacyFeatureConverterDbContext.cs` — Base EF Core DbContext with DbSets for History, Logs, Queue. Configures relationships, indexes, cascade deletes via `OnModelCreating`.
- `LegacyFeatureConverterDbContextSqlServer.cs` — SQL Server provider variant (inherits base DbContext)
- `LegacyFeatureConverterDbContextSqlite.cs` — SQLite provider variant (inherits base DbContext)

### Files in `.Data/Migrations/`

- `LegacyFeatureConverterDatabaseMigration.cs` — Runs EF Core `MigrateAsync` at `RuntimeLevel.Run` via `INotificationAsyncHandler<UmbracoApplicationStartingNotification>`
- `LegacyFeatureConverterDbContextFactory.cs` — `IDesignTimeDbContextFactory` for `dotnet ef` CLI tooling
- Auto-generated EF Core migration files for both SQL Server and SQLite providers

### EF Core registration pattern

Uses Umbraco's `AddUmbracoDbContext` extension in the Composer to detect the database provider from connection strings config and register the appropriate provider-specific DbContext. Same proven pattern as the reference project.

**Reference:** `Old__...\Data\` and `Old__...\Migrations\` — exact same EF Core pattern with `AddUmbracoDbContext`.

## Phase 3: Converter Infrastructure Services

**Goal:** Implement discovery, history, and queue services.

### Files in `.Infrastructure/Services/`

- `ConverterService.cs` — Takes `IEnumerable<IPropertyConverter>` via DI for auto-discovery (no reflection needed; Umbraco's DI handles it). This is how consumers add their own converters: register `IPropertyConverter` in their Composer.
- `ConversionHistoryService.cs` — EF Core CRUD for history + log entries via the DbContext from the Data project
- `ConversionQueueService.cs` — EF Core database-backed FIFO queue. Survives restarts. Serializes ConversionOptions to JSON column.

## Phase 4: Nested Content → Block List Converter

**Goal:** First working converter, TDD.

### Files in `.Converters/NestedContent/`

- `NestedContentConverter.cs` — Extends BasePropertyConverter
  - `CreateTargetDataTypeAsync`: NC config → BlockList config (content types → blocks, min/max → validation limit)
  - `ConvertPropertyValueAsync`: Parse NC JArray → resolve ncContentTypeAlias → create UDIs → build BlockList JSON. Handles nested NC recursively.
- `NestedContentConstants.cs` — Fields to strip: `ncContentTypeAlias`, `key`, `name`, `PropType`
- `BlockListModels.cs` — Serialization DTOs

**Reference:** `Old__...\Converters\NestedContentConverter.cs` (379 lines) and `Old__...\Services\AutoBlockListService.cs` (ConvertPropertyValueToBlockList, ConvertNCDataToBLData methods).

### Key patterns from reference:
- Use `JArray` deserialization (not `Dictionary<string,string>`) to handle JSON-serialized string values
- Check for `ncContentTypeAlias` key to distinguish actual NC from other JSON arrays (media pickers, etc.)
- `continue` on failures (not `return null`) to avoid aborting entire conversion
- Track already-processed compositions in `HashSet<int>` to prevent double-saves

## Phase 5: Background Job + Queue + SignalR

**Goal:** Async execution with real-time progress, restart survival.

### Files in `.Infrastructure/Queue/`

- `ConversionBackgroundTask.cs` — `IHostedService` / Umbraco `RecurringHostedServiceBase`. Polls queue every 5s. On startup, resets orphaned `Running` items to `Queued`. Supports `RunTestFirst` (test run first, then real if test succeeds). Suppresses notifications during conversion via scope options.

### Files in main plugin project

- `Hubs/ConversionHub.cs` — SignalR hub
- `Hubs/IConversionHubClient.cs` — Client interface: `ReceiveProgress`, `ConversionCompleted`
- `Hubs/ConversionHubRoutes.cs` — Maps hub to `/umbraco/LegacyFeatureConverter/ConversionHub`

  - `GET GetDocumentTypes(converterName)` — affected doc types

## Testing Strategy

**Framework:** MSTest + Moq + In-memory SQLite for EF Core tests

### Test structure
```
Tests/
  Abstractions/Models/       — ConversionResult, ConversionOptions computed properties
  Abstractions/Converters/   — BasePropertyConverter 4-phase workflow (mocked Umbraco services)
  Data/                      — EF Core DbContext CRUD, cascade deletes, queue FIFO
  Infrastructure/Services/   — ConverterService discovery, HistoryService lifecycle, QueueService
  Converters/NestedContent/  — Data conversion: simple/multi/nested/null/unknown alias
  Converters/MediaPicker/    — UDI parsing: single/multi/empty/invalid
  Controllers/               — Status codes, validation, authorization
```

### Mocking approach
- `IScopeProvider` → Mock `IScope` tracking `Complete()` calls (verifies test-run behavior)
- `IDataTypeService` → Mock GetDataType/Save with in-memory dictionary
- `IContentTypeService` → Mock GetAll/Get/Save with fake content types
- `IContentService` → Mock GetPagedOfType/Save

### Priority: Data conversion tests first (pure logic, highest value), then services, then workflow, then controllers.

## Key Architectural Improvements Over Reference Project

1. **Queue-based** instead of synchronous HTTP execution (prevents timeouts)
2. **CancellationToken** support for graceful cancellation
3. **Composition deduplication** via `HashSet<int>` (prevents double-saves)
4. **StopOnError** option (user choice between fail-fast and continue)
5. **RunTestFirst** option (automatic test→real pipeline)
6. **Notification suppression** during bulk saves (performance)
7. **Restart recovery** for orphaned queue items
